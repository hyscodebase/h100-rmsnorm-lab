# Measure restoration and RMSNorm separately with eight streams

At 128 × 4,096, the 16-warp kernel improved single-operator latency by about 15% against the 8-warp kernel. The sustained eight-stream result placed the two Triton kernels within the same throughput band when each graph also restored both BF16 input buffers. Test whether a separately timed RMSNorm stage retains at least 5% higher throughput with 16 warps under the same concurrency. Keep released vLLM as the second reference. [Eight-stream throughput results](SUSTAINED_128_REPORT.md)

Give each of eight streams the same 32 disjoint input pairs and work addresses across the three implementations. Compare two schedules with identical input values. Each combined replay runs restoration and RMSNorm in a single graph per stream. Each split replay runs two graphs per stream with a CUDA-event barrier across all eight streams between the reset graph and the operator graph. Queue both stages and their events before waiting for completion. Capture initial, restoration-complete and operator-complete events on a coordinating stream. The split measurement separately reports the restoration interval, the operator interval and wall time. Report total wall throughput for both schedules, which include graph dispatch and synchronization.

Use seed 141 for the standalone numerical checkpoint, with both schedules. Poison the work buffers, verify the restored inputs and BF16 rounding probes, compare both outputs with vLLM, and check all source digests. Measure independently on seeds 142–144 only if qualification passes. For each seed run three balanced rounds with both schedules for each backend. Warm up for at least one second and run each measured period for at least four seconds. Schedule one replay per stream per measured observation so both schedules process exactly 256 input pairs; record every original CUDA event interval and completed row count. Check both outputs at the end of each period.

Rotate the seeded backend order across the three rounds. Keep the two schedules adjacent for each backend and alternate their order by round and backend. Use the sum of coordinated CUDA intervals as the device time within a block, and use the original monotonic window as wall time. Take each rate's median across three blocks. Compute restoration fraction from the sum of the restoration intervals divided by the sum of the split CUDA intervals for that backend and seed.

Accept the concurrency hypothesis if the median operator-stage row rate in the split schedule is at least 5% higher than the 8-warp rate in every seed. In each seed, retain the fraction of the coordinated GPU interval spent in restoration, both wall rates and the vLLM comparisons. Record NVML activity and power with their original sampling boundaries to interpret the device load. The split schedule introduces a cross-stream stage boundary, which is part of the measured workload.
