# Test copy-free residual RMSNorm across vLLM's 256-row boundary

At 255 rows, the copy-free comparison uses the 16-warp reduction that matches released vLLM below 256 rows. At 256 rows, vLLM 0.10.0 switches its launch to 256 threads per block. Its lanes accumulate both eight-element groups before the warp reduction. Test whether fusion still improves throughput when both copy-free implementations follow that order. [255-row results](COPY_FREE_ROWS_255_REPORT.md) · [Released dispatch](https://github.com/vllm-project/vllm/blob/v0.10.0/csrc/layernorm_kernels.cu#L161-L199) · [Previously verified 256-row operator](TRANSFER_REPORT.md)

Reuse the ordered eight-warp shuffle from the earlier in-place kernel. Give the fused kernel immutable activation, residual and weight inputs and two disjoint writable outputs. In the split control, reuse the pinned vectorized 2,048-element BF16 addition. Its normalization must use the same ordered eight-warp reduction and BF16 rounding as the fused kernel. Verify both load/store layouts and the five shuffle stages and keep all binaries fixed after qualification.

Use 256 × 4,096 BF16, eight CUDA streams, 32 independent pairs per stream, and the same output addresses. Compare with released vLLM using restoration copies. Seed 157 independently checks both outputs, original input and weight hashes, signed zero, BF16 rounding and output alias guards. Also record the prior 16-warp kernel's numerical output at 256 rows to measure the dispatch boundary directly.

If the exact eight-warp implementations qualify, run seeds 158–160 independently. Use three balanced periods per backend in each seed, at least one second of warm-up and six seconds of timing per period, and 32 graph replays per stream per burst. Extend the recommendation only if the fused graph leads the matched copy-free two-kernel control by at least 5% in every seed. Save original CUDA and wall time intervals, throughput counts, direct NVML and coverage, binary identities, and a cache-only recovery check.
