# Match the serving kernel's FP32 reduction order

The vLLM 0.10.0 and four-warp Triton kernels rounded from different sides of a BF16 midpoint at 47 rejected seed-114 positions. Both outputs individually matched the two interval endpoints at all 47. Three fresh seeds failed the registered pairwise gate before timing. [Measured results](REPORT.md) · [Seed 114 outputs by coordinate](results/bounded-disagreements.json)

The release kernel uses up to 256 threads for this token count and partitions aligned BF16 rows into groups of eight. It accumulates FP32 squared pairs within each group and reduces across a block. Test a grouped eight-warp Triton candidate with that local accumulation order. Keep the input mutation, updated residual rounding, pre-weight BF16 rounding and output contract identical. Record the actual instructions and launch configuration before interpreting any numeric change. [vLLM launch](https://github.com/vllm-project/vllm/blob/v0.10.0/csrc/layernorm_kernels.cu#L68-L92) · [Accumulation order](https://github.com/vllm-project/vllm/blob/v0.10.0/csrc/type_convert.cuh#L134-L149)

First reproduce the failure at seed 114 and see whether the changed candidate clears the 47 decisions. Next validate fresh seed 117 with the same eight fixtures, exact residual and signed-zero checks, and the same pairwise boundary rule. Use seeds 118–120 for three independent measurements after numerical qualification. Each run retains 32 independent buffer pairs and uses the existing untimed restoration procedure. Recommend the candidate only if all three seeds pass the numerical gate and show a reduction of at least 5% against the original vLLM release kernel.
