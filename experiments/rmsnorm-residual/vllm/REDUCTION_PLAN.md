# Match the serving kernel's FP32 reduction order

The vLLM 0.10.0 and four-warp Triton kernels rounded from different sides of a BF16 midpoint at 47 rejected seed-114 positions. Both outputs individually matched the two interval endpoints at all 47. Three fresh seeds failed the registered pairwise gate before timing. [Measured results](REPORT.md) · [Seed 114 outputs by coordinate](results/bounded-disagreements.json)

The release kernel uses up to 256 threads for this token count and partitions aligned BF16 rows into groups of eight. It accumulates FP32 squared pairs within each group and reduces across a block. Test a grouped eight-warp Triton candidate with that local accumulation order. Keep the input mutation, updated residual rounding, pre-weight BF16 rounding and output contract identical. Record the actual instructions and launch configuration before interpreting any numeric change. Recommend the candidate only if all three seeds pass the numerical gate and show a reduction of at least 5% against the original vLLM release kernel.

## Arithmetic order and reproduction gate

The candidate assigns two groups of eight to each of 256 logical lanes. Each group adds successive adjacent squared pairs in FP32. Each logical warp combines pairs of lanes at distances 1, 2, 4, 8 and 16. It combines the eight warp sums in increasing order. The launch uses eight physical warps. Compiler output provides evidence of the actual layout and instructions. This order follows the inspected default CUB warp-reduction algorithm as a hypothesis about the pinned wheel. [CUB thread-block reduction](https://github.com/NVIDIA/cccl/blob/v2.7.0/cub/cub/block/specializations/block_reduce_warp_reductions.cuh#L127-L182) · [CUB warp steps](https://github.com/NVIDIA/cccl/blob/v2.7.0/cub/cub/warp/specializations/warp_reduce_shfl.cuh#L496-L502)
