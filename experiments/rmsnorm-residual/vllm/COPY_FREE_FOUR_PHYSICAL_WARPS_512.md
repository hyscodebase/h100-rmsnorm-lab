# Map eight ordered RMSNorm groups onto four physical warps

At 6,144 downstream columns, the eight-warp fused residual kernel cleared the registered 1% chain throughput improvement in one of three exact independent seeds. Test a new implementation at the isolated 512 × 4,096 residual shape to see whether there is enough kernel-level headroom to retest the chain. [Chain result](PROJECTION_TAIL_6144_REPORT.md) · [Tracking issue](https://github.com/hyscodebase/h100-rmsnorm-lab/issues/48)

Keep the released vLLM operator's 256 logical lanes. Physical lane index `p` handles logical lanes `p` and `p + 128`. Each logical lane keeps its two groups of eight BF16 elements, the same pairwise FP32 square sum, and a separate warp shuffle sequence with distances 1, 2, 4, 8 and 16. Each physical warp writes its two totals into the original logical slots. Sum all eight totals in the original order. Keep the intermediate BF16 residual and normalization rounding points and write both outputs to disjoint buffers. Fix the existing eight-warp fused binary as the throughput baseline.

Run seed 189 for numerical qualification. Use the same eight fixtures and capture checks against released vLLM, eight CUDA streams and 32 disjoint pairs per stream. Check both outputs bitwise after poisoning the buffers, verify alias guards and input and weight digests, and record the kernels' instructions, register and spill counts, vector global loads and stores, and barrier. Verify the baseline cubin and canonical PTX against the earlier isolated result. [Baseline kernel](eight_warp_outputs.py) · [Baseline measurements](SPLIT_ADD_TILES_512_REPORT.md)

Then time independent seeds 190–192 one at a time, with two balanced periods per path and at least one second of warm-up and six measured seconds per period. Use 32 graph replays per stream per burst. Require at least 5% more throughput over the current eight-warp path in every exact timing seed before transferring the candidate into the 6,144-column chain. Preserve measured periods, correctness, compiler output, raw device samples, attempt records and cache-only recovery.
